An **Agent** is a system that uses an AI model, usually an [[LLM]], to interact with its environment and achieve a goal set by the user.

Instead of only generating text, an agent can reason, plan and take actions, usually through [[AI Tools]] such as web search, APIs or running code. It works in a loop: it thinks about the next step, acts, looks at the result, and repeats until the task is done.

The term comes from _agency_: the ability to act and make decisions independently.

## Explanation

### Brain and body

An agent has two main parts:

1. The brain (AI model): where the thinking happens. The model handles reasoning and planning, and decides which actions to take based on the situation.
2. The body (capabilities and tools): everything the agent is equipped to do. The actions it can take depend on the tools it has been given.

### Which AI models are used?

The most common model in agents is an [[LLM|LLM (Large Language Model)]], which takes text as input and produces text as output. Well-known examples are GPT-4 from OpenAI, Llama from Meta and Gemini from Google. These models are trained on vast amounts of text and generalise well.

Models that accept other inputs can also be used. For example, a [[VLA|Vision Language Model (VLM)]] works like an LLM but also understands images.

### Tools and actions

An agent can perform any task that is implemented through [[AI Tools]]. The design of the tools has a big impact on the quality of the agent: some tasks need very specific tools, while others can be solved with general-purpose ones like `web_search`.

Actions are not the same as tools. An action is a step the agent takes, and a single action can involve several tools.

Actions can serve different purposes:

|Type of action|Description|
|---|---|
|Information gathering|Web searches, database queries, retrieving documents|
|Tool usage|API calls, calculations, executing code|
|Environment interaction|Manipulating digital interfaces or controlling physical devices|
|Communication|Chatting with users or collaborating with other agents|

### The core cycle: Thought → Action → Observation

- Thought: the LLM decides what the next step should be.
- Action: the agent calls a tool with specific arguments.
- Observation: the tool's result is added to the context, and the model reflects on it.

It works like a while loop: it repeats until the goal is reached, and then the agent gives the final answer. The rules of the cycle (agent behaviour, available tools, format) are written into the system prompt.

### Thought

The Thought is the agent's internal reasoning and planning: breaking a problem into steps, analysing observations and adjusting the plan. Common types are planning, analysis, decision making, problem solving, memory integration, self-reflection, goal setting and prioritisation.

Ways of making a model reason:

- Chain-of-Thought (CoT): a prompting technique that makes the model reason step by step, without tools. Best for logic and maths.
- ReAct (Reasoning + Acting): a prompting technique that alternates reasoning with actions using tools and their observations. Best for tasks that need information lookups or several dynamic steps.
- "Thinking" models (DeepSeek-R1, OpenAI o1): they reason before answering because they were trained to, using tokens like `<think>...</think>`. This is a training-level technique, not a prompting technique like CoT or ReAct.

For models fine-tuned for function calling, the Thought step is optional.

### Action

Agents differ in how they express their actions:

|Type of agent|How it acts|
|---|---|
|JSON Agent|Writes the action as JSON (tool name + arguments)|
|Code Agent|Writes a block of code that is executed externally|
|Function-calling Agent|A subtype of JSON Agent, fine-tuned to generate a separate message for each action|

Stop and parse:

1. The model writes the action in a structured format (JSON or code).
2. It stops generating once the action is complete.
3. An external parser reads which tool to call and with which arguments.

Why stop? The LLM only produces text. If it doesn't stop, it invents the Observation itself (hallucination) instead of waiting for the real tool result.

Code Agents:

- Advantages: expressiveness (loops, conditionals), modularity and reusability, easier debugging, and direct integration with libraries and APIs.
- Risk: running code generated by an LLM can be dangerous (prompt injection, harmful code). That's why frameworks like smolagents include safeguards.

### Observation

The Observation is how the agent perceives the result of its actions: the feedback from the environment.

The agent collects the feedback → appends it to the context (at the end of the prompt, updating its memory) → adapts its next steps.

Types of observations: system feedback (errors, status codes), data changes, environmental data (sensors, metrics), response analysis (API results) and time-based events.

After an action, the framework does three things in this order: parse the action → execute it → append the result as an Observation.

## Key points to remember

- CoT vs. ReAct: both reason step by step; only ReAct uses tools.
- Prompting vs. training: CoT and ReAct are prompting techniques; `<think>` models were trained to reason.
- Why stop generation? So the model doesn't invent the Observation, and so the output can be parsed.
- Order after an action: parse → execute → append.
- Where is the Observation added? To the context, at the end of the prompt.
- What a tool needs in smolagents: types plus a docstring describing every argument.
- Function-calling agent: a subtype of JSON agent.
